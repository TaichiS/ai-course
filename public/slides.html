Agent Skills
使用指南

讓 AI 記住你的工作方式

主講：詹嘉隆（阿隆）

從雇一個助理說起

想像你雇了一個新助理，第一週每件事都要手把手教：

  • 格式
  • 邏輯
  • 注意事項

如果你能把這些全部寫成一份說明書，下一個助理直接照做，不用重教——

Agent Skill 就是那份說明書，只是對象換成了 AI。

星巴克「老樣子」理論

每次點咖啡都要說：

「我要大杯、燕麥奶、少糖、不加糖漿、冰的、拿鐵」

花三十秒，店員也容易聽錯。

但如果你是常客，說一句 「老樣子」，對方就知道要做什麼。

Skill 就是那句「老樣子」

這跟一般 AI 對話有什麼差？

一般對話Agent Skill
每次重新說明一次設定，重複使用
輸出品質不穩定執行品質一致
換人要重新教團隊共用
上次調好的格式，下次重來永久保存設定

跟把指令存在記事本有什麼不一樣？

概念類似，但 Skill 多做了幾件事：

自動識別觸發

AI 看到任務就自動套用

結構化定義

適用情境、工具、步驟

團隊共用

一個人建好，所有人執行品質一致

GPT / Gem vs Skill

GPT / Gem

  • 一個功能一個入口
  • 整理週報 → 點週報 GPT
  • 回覆 email → 點 email GPT
  • 任務切換 = 在不同對話跳來跳去

Skill

  • 同一個對話，隨時呼叫不同 skill
  • 甚至可以一個任務同時用好幾個

真實場景：週報整理

沒有 Skill

  • 每次重新說明格式
  • 輸出品質不一樣
  • 忘記說「不要廢話」→ 來了一堆廢話

有了 Skill

  • 「幫我整理這週週報」
  • AI 自動套用預設格式、語氣、欄位
  • 同事也能用，不用重新交代

一個 Skill 長什麼樣子？

核心是一份 Markdown 檔案（SKILL.md）

回答三個問題：

1. 名字和觸發時機

什麼時候用它？

2. 能用哪些工具

Google Drive？網路查詢？

3. 執行流程

步驟、注意事項、輸出格式

Skill 資料夾結構

weekly-report-skill/ ├── SKILL.md ← 必要：主設定 ├── reference.md ← 選用：參考資料 ├── template/ ← 選用：輸出模板 └── scripts/ ← 選用：執行腳本

大多數情況，只需要 SKILL.md 就夠了。

Skill 的真正威力：呼叫工具

不只是「整理文字」，還可以：

存取 Google Drive

自動抓雲端筆記

查網路資訊

補充相關資料

產出 Word/PDF

直接輸出可用文件

按需加載

需要時才啟動，不搶資源

MCP 是什麼？跟 Skill 的關係？

比喻
MCP餐廳後台的進貨通道
Skill廚師的食譜

分工：

  • MCP 解決「AI 能不能拿到資料」
  • Skill 解決「拿到後該怎麼處理」

怎麼建一個 Skill？

不需要會寫程式！

方法一：Skill Creator

「幫你建 skill 的 skill」

用白話描述需求，它幫你生成 SKILL.md

方法二：跟 Claude 對話

來回幾輪講清楚流程

請 Claude 打包成 SKILL.md

Skill 的限制

維護成本

流程改了，skill 也要更新

記憶問題

不會記得你上次說了什麼

「打架」問題

多個 skill 條件重疊時可能衝突

最適合的場景：流程清楚、重複發生、有固定輸出格式的任務。

Agent Skills 不是 Claude 專屬

已經是主流 AI 工具的共同規格：

平台資料夾位置
Claude Code.claude/skills/
Gemini CLI.gemini/skills/
OpenAI CLI.openai/skills/
Cursor / Windsurf專案目錄下

同一份 SKILL.md，跨工具都能用！

從哪裡開始？

想想這個月重複做了三次以上的事：

  • 每次都要重新解釋格式？
  • 每次都要貼上相同的背景資料？

那個就是最值得先建成 skill 的任務。

重點回顧

1. Skill = AI 的「老樣子」

預設好的工作流程

2. 一次設定，重複使用

品質一致

3. 可以呼叫工具

Drive、網路、文件產出

4. 跨平台通用

團隊共用

5. 從最痛的重複工作開始建立
